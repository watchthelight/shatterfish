# Baseline at upstream v4.0.2

**A direction check, not an acceptance.** Nothing here ran under a Registration and no sequential
test was run. This page gives the pinned tag `v4.0.2` a baseline of its own, as the upstream-sync
procedure asks, and shows what the tag change alone does to the same Brain.

Upgrade PR for `v4.0.2` ([`docs/UPSTREAM.md`](../UPSTREAM.md)). Turn cap 20,000; the `shatterfish`
Brain on the weights in `weights/shatterfish.json`; Oracle off. The Brain is the same on both sides:
the left column is `main` (`9a97206d3`, upstream `v4.0.0`), the right is the upgrade branch
(`feb88de55`, upstream `v4.0.2`). Both were played on the same machine on 2026-10-25 with
`./gradlew :rig:direction --args="--set <set> --class WARRIOR --first 40 --salt-base 1000 --jobs 2"`,
run once in a checkout of each. The direction tool's `--baseline <git-ref>` option could not be
used: it swaps the baseline's Brain into the current build, and a build at `v4.0.2` has no
`codex/v4.0.0` to hand that Brain.

The `standard` triples are the same seeds on both sides, but a seed does not make the same dungeon
at `v4.0.2`: `RegularPainter` and `Statue` draw from the generator differently
([`docs/rules/levels.md`](../rules/levels.md)), so the Runs are different Runs, not a replay.

## Reading it

On 40 triples a difference of a few Runs in depth-5 reach or Goo kills is inside what a different
set of dungeons does by itself; no sequential test was run and none of this is a claim that the
tag helps or hurts the Brain. What it does show is that the Brain plays the new tag end to end:
no Run failed to finish on either set, and no number moved by an amount that points to a harness
gap. The `smoke` rows have five Runs each and say almost nothing.
