# The E7 Brain on the `holdout` set

The one release-level confirmation run of the final E7 Brain, under Registration H-0009. This page puts it beside the `standard`
numbers of [story 7.10](2026-10-27-7-10-the-measured-win-rate.md). **The Brain won no `holdout` Run**, as it won none on `standard`.
The generated page of the run itself, with its Registration, claim, command and data folder, is
[H-0009](2026-10-27-H-0009.md).

No win rate was set to beat (settled with the product owner on pull request #289), so nothing here passes or fails, and the measure
was not changed.

## What was run

- **The go-ahead.** The product owner gave it on [pull request #329](https://github.com/watchthelight/shatterfish/pull/329#issuecomment-6440993127)
  ("You can go-ahead on all.", 2026-10-27). The Registration cites it.
- **The Brain.** The same Brain story 7.10 measured: `shatterfish` on `weights/shatterfish.json` and `playbooks/shatterfish.json`,
  Brain version `1da06b9` (the last commit that changed the Brain's source, which the Rig's ledger keys the `holdout` allowance on) and
  configuration hash `25df9250ab11b8f01205a59ead52a4d8c70afd7ad745e44eba0aebcf281f8c8e`, the same hash H-0008 records.
- **The checkout.** The run was made from the story 7.10 merge commit `c46db8309` plus one commit that added the Registration, and
  not from the later `main`. Epic 8's first stories change the Decision record (story 8.1 adds Evaluation terms), which is a change
  to Brain source files and would have moved the Brain version, so the exact Brain that 7.10 measured on `standard` is the one that
  was run here. This page and its tests were then rebased onto `main`; nothing else changed.
- **The Registration.** `H-0009-shatterfish-holdout-e7-confirmation`: a baseline (one Brain, no test) with `release_level: true`,
  committed before the first Run, with a claim that fixes a measurement and no target.
- **The command.** `./gradlew :rig:run --args="--brain shatterfish --seeds holdout --parallel 4 --out <dir> --registration H-0009-shatterfish-holdout-e7-confirmation"`,
  with the Rig's turn cap of 20,000, as for `standard`. 500 Runs, every triple of `holdout` version 1, all six classes, one
  invocation, no restart and no resume. The first attempt stopped before it read the set, because the Registration reader refused
  a claim with a run of eight hexadecimal digits in it (a comment number); the claim was reworded, and the set was read only by the
  invocation that ran. The ledger shows the single `holdout` use.
- **Reading the set afterwards.** Writing up the data folder needed the set's version, and `Results.extract` read the set through the
  development door, which refuses `holdout`. It now reads it through `SeedSets.publish` when the Runs carry a Registration, with the
  Registration as the reason. That read plays nothing and records nothing in the ledger.

## What the numbers can and cannot show

- **A win is a Run that ascends with the Amulet.** Zero wins in 500 Runs has an upper limit under 1% on either interval, as on
  `standard`: the rate of this Brain on this set is very probably under 1%, and the run cannot tell 0% from 0.5%. The slices are
  smaller and their upper limits are about 4%.
- **Held out, so a fair comparison of reach.** The Brain was tuned on `standard` slices and never saw a `holdout` triple. The reach
  and Goo-kill rows are therefore the honest estimate of how much of the E7 movement carries over; compare the two columns row by row.
  They are one pass each of one machine's draw of salts, not paired Runs, and no Sequential test was run.
- **It cannot say why.** The log records the ending and depth, not the killer.
- **One allowance.** The Brain version's single `holdout` use is spent. A later Brain version has its own, by the ledger's rule, but
  the set is no longer unseen: its triples and this Brain's results on them are public.
