# Codebase map

File to mechanic, for the pinned upstream tag `v3.3.8` (see [Upstream](UPSTREAM.md)). Every
statement here was read from the code in bootstrap session 10 and is cited in the linked
[Rules](rules/index.md) page for its area; nothing on this page comes from memory, a wiki, or a
forum. Paths shorten `core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/` to `…/`.

!!! note "How this page was made"
    The bootstrap prompt asked for BMAD's document-project workflow. That skill is deprecated
    (its successor writes an `AGENTS.md` block, not a mechanics map), so session 10 ran eleven
    parallel upstream-reading subagents, one per area, each bound to the
    `upstream-reader` rules: read the pinned code, cite `path:line`, say what could not be
    settled. Their rules tables became `docs/rules/<area>.md`; their file tables are below; their
    claim checks produced the discrepancies table. Re-run the same fan-out after an upstream
    upgrade (`docs/UPSTREAM.md`, step 9).

## What the architecture must absorb

Findings that change a design assumption, each with the epic it lands in.

- **Turns resolve on the actor thread and wait on sprites (E1).** `Actor.process` blocks on `sprite.wait()` while a `CharSprite` is moving, and the hero's attack, operate, zap and read actions end their turn in animation callbacks fired from `MovieClip.update` or `Tweener.update` on the render thread. `Hero.ready` and `Hero.interrupt` dereference `AttackIndicator.instance` and `GameScene.cellSelector` unconditionally. A headless driver therefore needs a scene with a hero sprite whose parent group is updated, plus the `GameScene` statics, or hooks at those points. Unseen mobs never animate, so only the hero's sprite gates time.
- **The turn counter lags (E1).** `Statistics.duration` advances only in `Actor.fixTime` (save, level change, death). Elapsed turns at any instant are `Statistics.duration + Actor.now()`; the Harness counts from that, never from `duration` alone.
- **Seed the base generator after `Dungeon.init` (E1).** `Dungeon.init` seeds the per-run state under `seed+1` and then calls `Random.resetGenerators()`, which replaces the stack with a fresh unseeded base. Determinism also needs a fresh Profile (no `bones.dat`, `journal.dat`, `settings.xml` from other runs), the guide-page generator neutralized, and no render or audio thread sharing the generator during a headless Run.
- **Identity-hash order is a nondeterminism source (E1).** Equal-time, equal-priority actors are picked in `HashSet` iteration order, and `Random.chances(HashMap<Class, Float>)` depends on class identity hashes inside seeded level generation. The E1 determinism test must run two Runs in two JVMs, not one JVM twice.
- **A floor is (seed, challenges, history), not (seed, depth) (E1, E3).** Generator decks and `LimitedDrops` carry across floors and are advanced by player actions (grass seeds, quest rewards), so a Run's item sequence depends on the action list. This is what the Run log's replay must reproduce; it is not a defect.
- **The Observer's legal sources (E1).** `heroFOV`, `visited`, `mapped`, `discoverable`, `Level.secret` only through `map` values, `Trap.visible`, `Heap.seen` and container types, `Item.name/isIdentified/levelKnown/cursedKnown/visiblyUpgraded/visiblyCursed/status/actions`, `Wand.curChargeKnown`, `Ring.isKnown`, `Potion/Scroll/Ring.getKnown`, buffs with icons, `Blob.cur` masked by `heroFOV`, the mob sprite's `visible`, `WndInfoMob`'s buff row, the game log. Never: an unknown item's class, `Item.level()` or `cursed` when unknown, ID progress counters, `ItemStatusHandler.unknown()`, `Level.mobs` positions outside `heroFOV`, `Blob.cur` outside `heroFOV`, the cell selector's hit test, the exact hunger value.
- **Boss floors lock at the arena trigger (E4, E7).** `Level.locked` blocks every transition and interfloor teleport from the moment Goo notices the hero (or the hero crosses the arena line for the other four) until the boss's `die` or, for Tengu, the level's own progress machine.
- **Overlay geometry (E5).** The full UI gives 427 by 240 UI pixels at 1280x720; the free column between the menu pane and the inventory pane is 240 minus 21 minus 82 minus 26 (toolbar) tall. `GameScene`'s HUD fields are private and `cellSelector` is a private static, so the Overlay needs a hook to reach them; `Camera.main.setCenterOffset` is public but `layoutTags` overwrites it. F6 to F12 are unbound. UI text is a platform TTF through `renderTextBlock`, at sizes the game itself uses (6 for the log, 8 for toasts, 9 for buttons).
- **Prompts are not engine waits (E1, E5).** A `Window` blocks the player, not the actor thread; the hero is already `ready` when a quest or shop window appears, and a window opened mid-action leaves the actor thread running. The Harness models an Input wait as "hero ready and no blocking window", and answers windows through their own buttons, never by waiting on the engine.
- **Score and Win (E3).** The Composite outcome's Win is `Statistics.gameWon` as `Rankings.submit(true, ...)` records it; Score is `Rankings.calculateScore` with the challenge multiplier, so Scores compare only within one challenge set, as the PRD says.
