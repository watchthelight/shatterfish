# Spine Pair Review — Shatterfish Overlay

## Overall verdict
The pair is extractable: all three `sources` resolve, every `{path.to.token}` in both files resolves to a DESIGN.md frontmatter token, every color has a hex, and the DESIGN.md section order and EXPERIENCE.md defaults are in place. It is not yet a clean contract: four high findings are internal contradictions or silent drops that a story-dev would have to settle alone (the launch-time Mode and speed mode are never committed and Flow 1, Flow 2, and PRD UJ-2 each imply a different one; Interaction Primitives and State Patterns disagree on whether Next Step is enabled in RUNNING; the frontmatter sets the Goal line in `body` while the prose says title size twice; PRD FR-39's `Run N` control vanished without a recorded rejection). No critical findings. One Update pass with a control-enablement matrix, a launch-default row, and a name pass across the two files would bring it to strong; visual-reference coverage is pending on the two mocks in `.working/`.

## 1. Flow coverage — adequate
Sources frontmatter → PRD section 2.3 (UJ-1 to UJ-5) and section 4.6 (FR-37 to FR-47). Overlay journeys are UJ-2 and UJ-4; UJ-1, UJ-3, UJ-5 are Rig, reproduction, and upgrade journeys with no Overlay surface. Checked each of the five Key Flows for a named protagonist, numbered steps, a bold climax, and a failure path; checked each FR for a flow or a state that exercises it. UJ-2 → Flow 1 + Flow 2 (Bash, numbered, climax, failure path present). UJ-4 → Flow 5 (v2 stub). FR-37 launcher, FR-38 Panel, FR-40 interjection, FR-41 highlights, FR-42 hotkeys, FR-43 oracle all reached by a flow. FR-44, FR-46 (v2) have IA rows only, acceptable for deferred scope.
### Findings
- **high** The Mode and speed mode at launch are never committed. Flow 1 step 1 docks the Panel "in PAUSED, speed mode Next Step"; Flow 2 step 1 opens "RUNNING at Human play speed"; PRD UJ-2 says the Panel docks with "Mode RUNNING"; State Patterns has a launch default only for resume ("starts PAUSED regardless"). A story-dev implementing FR-37 has three answers (EXPERIENCE.md › Key Flows › Flow 1 step 1, Flow 2 step 1; State Patterns › Save and resume; PRD 2.3 UJ-2). *Fix:* add a "Fresh Run" row to State Patterns committing the launch Mode and speed mode (PAUSED + Next Step matches the TAS posture), and note the deviation from UJ-2's "Mode RUNNING" so the PRD can follow.
- **high** PRD FR-39 lists `Run N` among the v1 controls; it appears nowhere in IA, Component Patterns › Controls, Interaction Primitives, or Inspiration & Anti-patterns as a rejection. The memlog records the speed-mode decision replacing the turns-per-second cap but says nothing about Run N (EXPERIENCE.md › Component Patterns › Controls; PRD 4.6 FR-39). *Fix:* either add Run N (a count-limited Next Step: runs N hero turns then lands in PAUSED) to Controls and the Stepping model, or add a "Rejected: Run N" bullet with the reason and flag FR-39 for a PRD update.
- **medium** FR-45 Pause-on conditions (v2) has no surface. The IA closure paragraph claims "every stated need in PRD section 4.6 lands on one of these surfaces" and in the same breath says "there is no settings surface of the Overlay's own", yet FR-45 says "the user can set conditions". State Patterns › PAUSED mentions "a Pause-on condition (v2)" as an entry cause only (EXPERIENCE.md › Information Architecture; PRD FR-45). *Fix:* add an IA row for where conditions are set (launcher flags, a Controls toggle row, or the game's settings screen via an `SPDAction`-adjacent hook) marked v2, or drop the closure claim.
- **medium** FR-37 save-and-resume has a State Patterns row but no flow, and it is the one place where the Run log boundary, re-attach, re-plan, and forced PAUSED all have to happen in order; open question 10 in the PRD makes it the riskiest Overlay path (EXPERIENCE.md › State Patterns › Save and resume; PRD FR-37, section 13 Q10). *Fix:* a short Flow 6: save-and-quit mid-Run, relaunch, resume; climax is the Panel returning PAUSED with a fresh Decision and the log showing the boundary line.
- **low** Flow 5's protagonist is "A player / they" (unnamed) and it has no failure path; Flow 3 has no failure path (a death landing while THINKING, or the Run log path missing) (EXPERIENCE.md › Key Flows › Flow 3, Flow 5). *Fix:* name the learner; add one failure line each.
- **low** UJ-1, UJ-3, UJ-5 are excluded without saying so. *Fix:* one sentence in Foundation: "UJ-1, UJ-3, UJ-5 have no Overlay surface and are not specified here."

## 2. Token completeness — adequate
Extracted all frontmatter tokens: 14 colors (all hex, dark-only stated), 4 typography roles (fontFamily + fontSize; `numeric` carries a `note`), `rounded.DEFAULT`, 8 spacing entries (three by reference), 11 component objects. Resolved every `{path.to.token}` inside `components` and in the prose of both files: all 30-odd references resolve by name. Then compared frontmatter values against the prose that describes the same element.
### Findings
- **high** `components.goal-line.typography` is `{typography.body}` (8px), but the Typography section says "title 9 (the Goal line and section labels)" and Components says "Goal line. Title size". Downstream code mirrors the frontmatter, so the Goal line will ship one size smaller than the prose intends (DESIGN.md frontmatter › components.goal-line; body › Typography; body › Components › Goal line). *Fix:* set `typography: '{typography.title}'`.
- **medium** Probabilities: Typography prose assigns "small 6 (the decision log and probabilities)", but `components.belief-row.probability-typography` is `{typography.numeric}` (8px) (DESIGN.md frontmatter › components.belief-row; body › Typography). *Fix:* pick one; if probabilities are numeric columns they should be `numeric`, so amend the prose.
- **medium** No contrast target is stated anywhere, and EXPERIENCE.md › Accessibility Floor says "contrast and color meaning live in DESIGN.md". Load-bearing combinations with no target: `ink-muted` (#9C9C9C) at `small` 6px on `TOAST_TR_HEAVY` over the brightest dungeon tile; `warn`/`paused` amber and `ok`/`running` green on the same scrim; `ink-dim` (#5E5E5E) disabled controls (DESIGN.md › Colors; EXPERIENCE.md › Accessibility Floor). *Fix:* one line in Colors: the scrim's effective luminance, the ratio target for ink/ink-muted/flag colors against it, and a note that ink-dim is exempt as a disabled state.
- **medium** Mode-strip words `THINKING`, `ORACLE`, `RUN OVER` and the HUMAN-mode "greyed" Decision card have no token. `mode-strip` defines only `running`, `paused`, `human`; Oracle border implies `ORACLE` is `{colors.oracle}` but the strip does not say so; "greyed" could be `ink-muted` or `ink-dim` (DESIGN.md frontmatter › components.mode-strip, decision-card; EXPERIENCE.md › State Patterns › HUMAN, THINKING, Run over). *Fix:* add `thinking`, `oracle`, `run-over` to `mode-strip` and `ghost-ink` to `decision-card`, each by reference.
- **low** `components.map-highlight.target` is `{colors.danger}`, but the Colors prose says OK/Warn/Danger "are the Safety-flag semantics and nothing else" and "Avoid ... using red for anything but Danger and Oracle" (DESIGN.md › Colors; frontmatter › components.map-highlight). *Fix:* either state that the target cell is a Danger use ("the cell the hero will strike") or give the target its own token.
- **low** `rounded.DEFAULT: 'nine-patch'` is not a dimension, and `colors.panel-scrim: '#000000'` is referenced by nothing and describes a nine-patch, not a fill (DESIGN.md frontmatter › rounded, colors.panel-scrim). *Fix:* use the spec's `note` form for `rounded` (or omit the key; the Shapes section already says corners come from the frames) and drop `panel-scrim` or make it `{ note: 'Chrome.Type.TOAST_TR_HEAVY' }`.

## 3. Component coverage — adequate

### Findings
- **medium** Thinking indicator has a behavioral row (EXPERIENCE.md › Component Patterns) and a state (THINKING) but no DESIGN.md row and no token; a dev cannot render it (EXPERIENCE.md › Component Patterns › Thinking indicator; DESIGN.md › Components). *Fix:* fold it into Mode strip in DESIGN.md with its color, or give it a row.
- **medium** Name drift across the pair: DESIGN.md `Flag chip` vs EXPERIENCE.md `Safety flags`; `Belief row` vs `Belief summary` (EXPERIENCE.md uses both: Component Patterns says "Belief summary", Interaction Primitives says "click a Belief row"); `Control button` vs `Controls`; `Map highlight` vs `Map highlights`. - **low** Explain expansion is an IA surface with behavior in Decision card but no visual anatomy in DESIGN.md (Policy line, full reasons, applied flags, how the expanded card differs from the collapsed one) (EXPERIENCE.md › Information Architecture › Explain expansion; DESIGN.md › Components › Decision card). *Fix:* two lines under Decision card: expanded anatomy and which tokens each line uses.
- **low** Visual rules living only in EXPERIENCE.md, and unused vocabulary: Controls "in one row, wrapping to two" is layout; DESIGN.md › Typography names "section labels" at title size but no component or pattern mentions section labels; `Icons` is listed in the toolkit (both files) and used by nothing. *Fix:* move the Controls wrap rule to DESIGN.md › Components; either add section labels to Panel or delete the phrase; drop `Icons` or say where it is used.

## 4. State coverage — adequate
Walked every IA surface (Panel, Mode strip, Explain expansion, Map highlights, Key bindings, Launcher, Replay scrubber v2, Coach mode v2) against the states it should have: launch, RUNNING/PAUSED/HUMAN, over-budget, hero busy, no action, Run over, no Run, save/resume, oracle, collapsed, Brain error, interface sizes. Eleven State Patterns rows cover the ordinary set well; the misses are one contradiction and two absent states.
### Findings
- **high** Next Step enablement contradicts itself. Interaction Primitives: "Next Step: one hero turn, only in PAUSED; in RUNNING it pauses first (one press to pause, the next to step)", so it is enabled in RUNNING. State Patterns › RUNNING: "Next Step disabled unless speed mode is Next Step". And per the Stepping model, in Next Step speed mode the strip reads PAUSED between presses, so RUNNING × Next Step is a state that barely exists. Two implementations satisfy the spine and disagree (EXPERIENCE.md › Interaction Primitives › Next Step; State Patterns › RUNNING; Stepping model). *Fix:* replace the per-row control lists with one control-enablement matrix: rows Mode × speed mode (RUNNING/PAUSED/HUMAN/THINKING/Run over × Next Step/Human/Fast), columns Pause/Resume, Next Step, Speed selector, Take over/Hand back, Explain, Panel toggle; cell = enabled/disabled and effect.
- **medium** Resume in Next Step speed mode is undefined: the Stepping model says the bot acts only on a press, State Patterns › PAUSED lists Resume as enabled, Flow 1 step 6 only presses Resume after switching to Human (EXPERIENCE.md › Stepping model; State Patterns › PAUSED; Key Flows › Flow 1 step 6). *Fix:* a cell in the matrix above (disabled, or acts as Next Step).
- **medium** Brain failure has no state. "No valid action" covers an empty Decision and THINKING covers a slow one; an exception on the worker thread, or a THINKING that never lands, has no Panel treatment or resulting Mode (EXPERIENCE.md › State Patterns). *Fix:* a "Brain error" row: strip word, Decision card text, forced PAUSED, log line, Run log entry.
- **low** Interface size 1 (full layout without the inventory pane) is not in the Responsive table although research section 7 says the Panel may replace the inventory pane there; the table only covers "at least the minimum", "narrower or collapsed", and "mobile layout" (EXPERIENCE.md › Responsive & Platform). *Fix:* one row for size 1.
- **low** Launcher error states (missing seed, oracle flag together with a Rig flag) are unspecified; arguably CLI scope (EXPERIENCE.md › Information Architecture › Launcher). *Fix:* say "launcher errors are CLI text, out of Overlay scope" or add two lines.
