Working tree == v3.3.8 for every file cited (the only hook is `settings.gradle`, per `docs/UPSTREAM.md`).

**Question**: Does turn resolution at v3.3.8 block on, or get driven by, sprite animation (the render thread), and what would a headless build have to replace?

**Answer**: Yes on both counts, with one guard the red-team summary omits. The actor thread blocks in `Actor.process()` on `sprite.wait()` while `sprite.isMoving` is true (`core/actors/Actor.java:278-280`), and that block is skipped entirely when `sprite == null` (`Actor.java:274`). `isMoving` is set in `CharSprite.move()` (`core/sprites/CharSprite.java:226`) and cleared with `notifyAll()` only in `CharSprite.onComplete(Tweener)` (`CharSprite.java:824-835`), which is reached only from `Tweener.update()` (`noosa/tweeners/Tweener.java:46-67`) driven by `Game.update() -> scene.update()` on the render thread (`noosa/Game.java:281`); the only other releases are thread interruption (`Actor.java:283-284`) and TenguSprite, which clears the flag in its own `play()` and `onComplete` overrides (`core/sprites/TenguSprite.java:59-65,117-118`). Damage itself is synchronous inside `Char.attack()` (`core/actors/Char.java:368`), but the call to it is deferred to an animation callback: `Mob.doAttack()` calls `sprite.attack(enemy.pos)` and returns false (`core/actors/mobs/Mob.java:661-671`), and `Mob.onAttackComplete()` does the actual `attack(enemy)`, `spend()` and `next()` (`Mob.java:676-681`); `Hero.actAttack()` does the same (`core/actors/hero/Hero.java:1432`, `Hero.java:2311-2340`). `CharSprite.onComplete(Animation)` dispatches `animCallback` or `ch.onAttackComplete()` / `ch.onOperateComplete()` (`CharSprite.java:841-862`) and is called from `MovieClip.updateAnimation()` (`noosa/MovieClip.java:73-74`), again render-thread only. `Mob.doAttack()` has a synchronous fallback for `sprite == null` (`Mob.java:667-670`), but `Mob.act()` dereferences `sprite` unguarded before it (`Mob.java:233-237`), so that fallback is unreachable with a null sprite. Wand zaps are the same shape: `curUser.sprite.zap(cell)` then `curWand.fx(shot, callback)` where the callback runs `onZap` + `wandUsed` (`core/items/wands/Wand.java:710,766-783`), and `fx` fires from `MagicMissile.update()` (`core/effects/MagicMissile.java:294-303`); thrown items run `onThrow` + `spendAndNext` from `MissileSprite.onComplete(Tweener)` (`core/items/Item.java:642-680`, `core/sprites/MissileSprite.java:181-184`). Sprite construction needs GL: every concrete sprite calls `texture(Assets.Sprites.X)` (`core/sprites/RatSprite.java:32`, `HeroSprite.java:55`) -> `TextureCache.get` -> `new Pixmap(Gdx.files.internal(..))` and `new SmartTexture` (`noosa/gltextures/TextureCache.java:123,156`), and merely loading the `Texture` class dereferences `Gdx.gl` in static initialisers (`noosa/glwrap/Texture.java:34-39`). The bare `CharSprite()`/`MovieClip()`/`Image()` constructors do not touch GL (`CharSprite.java:131-134`, `MovieClip.java:37-39`, `Image.java:47-52`), but `play()` -> `frame()` dereferences `texture.width` (`Image.java:74-78`, `MovieClip.java:110`), so a texture-less sprite NPEs on its first animation unless `frame()` is overridden. Game logic synchronises on sprites in exactly two places (`Actor.java:278`, `core/actors/buffs/GravityChaosTracker.java:78`) and on the scene/actor thread in `GameScene` (`core/scenes/GameScene.java:797,885,1065`); every Noosa `Group` method is `synchronized` (`noosa/Group.java:45-316`). Nothing in the code references issue #431 or the word "deadlock".

## Strategy estimates (derived from the counts above; Shatterfish design notes, not upstream claims)

Paths below use the same abbreviations as the Answer.

- (a) Null sprites everywhere with guards. 969 `sprite.` dereferences across actors+items (596 + 373), of which ~72 lines are already guarded; `Mob.act()` (Mob.java:233-237), `Hero.ready()` (Hero.java:936) and `Char.moveSprite` (Char.java:313) sit on every turn. Turn completion for attack/operate/zap/throw additionally needs a synchronous replacement at the 30 `sprite.attack(cell, cb)`, 86 `sprite.operate`, 52 `sprite.zap` and the MissileSprite/MagicMissile callback sites, because with a null sprite those callbacks never fire and `next()` is never called (Mob.java:664-665, Hero.java:1432, Wand.java:766, Item.java:653). Not minimal: it is a hook touching hundreds of upstream lines.
- (b) Live sprites, no-op GL, driven update loop. Needs `Gdx.gl` non-null before `glwrap.Texture` class-loads (Texture.java:34-39), `Gdx.files` for `new Pixmap(Gdx.files.internal(..))` (TextureCache.java:156; Pixmap needs the gdx2d native), `Gdx.app` for `runOnRenderThread` (Game.java:307), `Gdx.graphics.getDeltaTime()` in `Game.update` (Game.java:271), and a live `GameScene` (or a Scene exposing `mobs`, `emitters`, `spells`, `statuses` Groups so `sprite.parent` is non-null, CharSprite.java:224). Turn completion then arrives by calling `scene.update()` repeatedly with a large `Game.elapsed` (Tweener.java:56-63 fast-forwards; MovieClip.java:63-74 wraps frames) until `Actor.processing()` is false. Zero upstream edits, but the entire rendering object graph is live and `GameScene.create()` builds tilemaps, fog and UI (GameScene.java:305-330 and following).
- (c) `HeadlessCharSprite`. The bare `CharSprite()` constructs without GL (Image.java:47-52). Overrides required: `frame(RectF)` (or a fake `SmartTexture` with width/height, since `frame()` at Image.java:74-78 and `play()` at MovieClip.java:110 dereference `texture`); `move(from,to)` (never set `isMoving`, no `parent.add`, call `ch.onMotionComplete()` directly; CharSprite.java:217-232); `attack/operate/zap(cell, Callback)` (invoke the callback or `ch.onAttackComplete()`/`ch.onOperateComplete()` synchronously instead of `play()`; :258-282, :841-862); `jump(...)` (call `jumpCallback` immediately; :294-307); `link(ch)` (skip `place`, `turnTo`, `CharHealthIndicator`; :145-164); `place`/`worldToCamera` (no `Camera.main`; :179-191); `showStatus*` (no FloatingText/`Gdx.app`; :193-211); `emitter/centerEmitter/bottomEmitter` (return a dead Emitter, not null, because callers chain `.burst()`; :321-337, Char.java:963); `bloodBurstA/flash/burst/add(State)/remove(State)/aura` (:339-486); `die()` (:309-319); `showAlert/hideAlert/showLost/hideLost/showInvestigate/hideInvestigate/showSleep/hideSleep` (:655-748); `update()`/`draw()` (no-op; :573, :777); `destroy()`/`kill()` (:167, :750).
