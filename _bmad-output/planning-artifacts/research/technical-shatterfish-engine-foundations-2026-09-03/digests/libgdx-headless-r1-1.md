### d) Precedent and multiple apps per JVM
- CLAIM: Because every HeadlessApplication constructor overwrites the process-global Gdx.app/files/net/audio/graphics/input statics, two HeadlessApplication instances in one classloader cannot coexist without the second clobbering the first's environment; libGDX offers no per-application context object. | SOURCE: https://raw.githubusercontent.com/libgdx/libgdx/master/backends/gdx-backend-headless/src/com/badlogic/gdx/backends/headless/HeadlessApplication.java (constructor) and https://raw.githubusercontent.com/libgdx/libgdx/master/gdx/src/com/badlogic/gdx/Gdx.java | PUBLISHER: libgdx/libgdx | PUB_DATE: unknown (master) | CONFIDENCE: high (derived from source; no explicit libGDX statement found) | CLASS: pattern

## Contradictions
- Release dates: the GitHub Releases fetch summarized 1.14.0 as "October 19, 2024", 1.13.5 as "May 13, 2024", 1.14.1 as "May 18, 2025" and 1.14.2 as "June 5, 2025" (and called 1.14.1 the "first 2026 release"), while libgdx.com/news dates 1.13.5 to 2025-05-13, 1.14.0 to 2025-10-20 and 1.14.1/1.14.2 to 2026-05-28. The libgdx.com ordering is internally consistent (1.13.1 < 1.13.5 < 1.14.0 < 1.14.1/2) whereas the GitHub summary is not (1.13.5 dated before 1.13.1), so treat libgdx.com as authoritative and the GitHub year values as a fetch-summarization error; re-verify tag dates directly next round.
- Headless viability: the backend README claims apps "designed without headless in mind will work as headless apps with minimal reconfiguration", while issues #3383/#5995 and the Perita post show that anything constructing Texture/SpriteBatch/ShaderProgram (i.e. most real games, including SPD's scene layer) NPEs on Gdx.gl==null. Both hold: logic-only code works; rendering-adjacent object construction does not.
