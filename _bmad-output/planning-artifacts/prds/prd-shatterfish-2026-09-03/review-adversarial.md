# Adversarial review of the Shatterfish PRD

## Verdict

Not as-is. The PRD's rule integrity is mostly structural and holds where the build enforces it (module edges, Oracle gating, no socket, native UI), but it leaves three side doors around Rule 1 that no listed test covers (Codex data flowing from `core` to `brain`, the valid-Action set, and seed memorisation through E9 labels and repeated public-seed iteration), contradicts itself on what PAUSED means versus HUMAN, and in the pre-win era its own Composite outcome rewards exactly the dive-and-die behaviour SM-C2 says it counterbalances. The UX workflow cannot derive a Panel state machine from what is written, the epics workflow will find at least seven FRs whose bullets belong to different epics (one, FR-26, cannot be done in the epic that owns it), and the architecture workflow has no defined per-pair statistic to build the Sequential test on. Every problem below is fixable with a sentence or a table; none needs a rewrite. Run a revision pass before the architecture workflow consumes this document.

Assumptions about the game used in front D are stated inline as `(assumption)` and are meant to be settled by the upstream-reader at the pinned tag, per Rule 8.

## A. Non-negotiable violations

- **[high]** The Codex is an unguarded second door from game state to the Brain (§3 Codex, §4.3 FR-14, §10 Module boundaries) — Rule 1 names "a single class named `Observer`" as "the only door from game state to the bot"; the PRD gives `codex` a dependency on `core` and makes Codex JSON "The Brain's only source of general game knowledge", so a data file generated by running game code reaches the Brain outside the Observer and outside every leak, differential, and ArchUnit test (FR-7 to FR-10 test classes and Observations, not data). FR-14's "parameterized by depth and challenge flags where the game's tables are" is generation by executing `core`; nothing requires that execution to be seed-free. *Fix:* add to FR-14 "Codex generation runs with no Dungeon, no seed, and no Run; a Codex leak test regenerates under two seeds and asserts byte-identical output; the Codex folder is the only non-Observation input the Brain may load and its path is fixed by the build."
- **[high]** E9 training labels can memorise seed-to-hidden-state (§4.2 FR-11, §6.2 E9, §5 non-goals) — FR-11 admits Oracle for "producing training labels for the optional E9". If label Runs use the public Seed sets, a learned Evaluation over Observation features (the drawn map identifies the seed) learns the true identity of the unidentified scroll on seed N. FR-9's differential test uses "a constructed world" and cannot catch a memorised mapping on real seeds; FR-13 does not apply to the Evaluation. *Fix:* FR-11 gains "label Runs use seeds disjoint from every committed Seed set; any learned component must pass FR-9's behavioral form on `standard` with hidden state permuted per seed."
- **[high]** The valid-Action set is a leak channel that no test lists (§4.1 FR-4) — "The set of valid Actions for an Observation is available to the caller." If the Harness computes it from game state, "attack cell X" being valid reveals an invisible or unseen mob, and "search" or "descend" validity reveals hidden features. FR-8's list (scroll, mob behind wall, secret door, trap, invisible enemy, seed, RNG) does not include it and the Observation hash does not cover it. *Fix:* state that the valid-Action set is a pure function of the Observation living in `api`, or make it part of the serialized Observation so FR-8 and FR-9 cover it.
- **[high]** The Codex "exports the hit-chance formula" is a second implementation of a rule and a folklore risk at once (§3 Evaluation, §4.3 FR-14, §4.5 FR-33, §5) — "the hit-chance formula the Codex exports from `Char.hit`": a generator can extract tables from code, not a formula; the formula will be hand-transcribed (Rule 8: settled only by citing, never by restating) and then evaluated inside `brain`, which the PRD's own non-goal forbids ("will not reimplement any game rule in any language"). Rule 4 permits "an abstract tactical model derived from Observations", not a copied engine rule presented as Codex output. *Fix:* replace "the Codex exports" with "a Tier-2 Rule: an approximation of `Char.hit` with `path:line`, verified by a Harness test against the engine at the tag"; align §5's non-goal to Rule 4's wording.
- **[medium]** Seed-specific knowledge can enter through Lore and Playbooks (§4.3 FR-18, §4.5 FR-35) — Lore admits "one file per claim with provenance"; a forum seed guide ("seed X has a ring of wealth on 2") has provenance, a variant, and could be Tier 1. Playbooks are "editable without code changes" and could key rules on floor layouts of public seeds. Rule 1 confines general knowledge to "the wiki-level facts the Codex extracts". *Fix:* add "No Lore, Rule, Playbook, or Evaluation datum may reference a seed, a Seed set, or a specific dungeon instance; the lore classifier rejects such claims; a data-file leak test greps Playbooks and Lore for Seed-set members."
- **[medium]** Fairness review scope omits every data channel (§8 NFR-1) — "A pull request touching the Observer, the ActionExecutor, or the Brain gets an adversarial fairness review." Not covered: `api` (the Observation schema itself), `codex` (the generator), Playbook and Lore files, Evaluation weight files, the Rig's seeding and snapshot code. *Fix:* extend the sentence to "`api`, `codex`, the Rig's seeding and snapshot code, and any Playbook, Lore, or weight file".
- **[medium]** Redetermination is silent about the RNG (§4.1 FR-6, §3 Search) — "every hidden element is re-sampled from a supplied Belief": a Belief holds no RNG state, so a redetermined copy that inherits the Run's random sources lets engine rollouts preview true combat rolls, which Rule 1 forbids ("RNG state, or the seed"). *Fix:* FR-6 consequence: "the redetermined copy's random sources are seeded from a Search-owned value never derived from the Run's RNG; the FR-9 'different RNG state' case is run on redetermined copies."
- **[medium]** Mechanics and UI claims stated without a citation route (Rule 8) — FR-38 "the free column between the menu pane and the inventory pane"; FR-2 "the general-purpose generator used for combat rolls"; FR-42 provenance "the research verified the binding Hook is small"; UJ-2 "the Panel shows PAUSED only once the hero is waiting for input"; FR-1 "Turn resolution paths that depend on sprite animation (attack, zap, throw, use)". None has a Rule ID or a `path:line`. *Fix:* tag each with "Rule R-n" or "confirm with upstream-reader before E-x" so FR-17 can enumerate them.
- **[medium]** The determinism tuple silently redefines Rule 5 and omits what the hash actually depends on (§3 Run, FR-2, NFR-2, §9) — Rule 5 says (upstream tag, seed, action list); the PRD says (Upstream tag, hero class, challenge flags, seed, Action list). Neither includes the Shatterfish commit, yet §9 says an Observation schema change "invalidates Replay", so NFR-2's "verify any published Run from the Run log and the pinned tag" is not sufficient. *Fix:* NFR-2 adds "and the Shatterfish commit named in the log"; the refinement of Rule 5 is called out as a `[NOTE FOR PM]`.
- **[medium]** Rule 3 has no budget while five FRs imply hooks (FR-1 static helpers, FR-37 launcher and the hero-ready observation point, FR-39 sprite-wait bypass, FR-42 key bindings) — SM-C5 says only "fewer is better" and FR-42's fallback triggers on "if the Hook is not small", which is unfalsifiable. *Fix:* state a v1 Hook count budget in §10 and define "small" for FR-42 as a line count.
- **[low]** FR-3's principle admits the drawn seed (§4.1 FR-3 versus FR-8) — "from what the game computes for drawing": the game draws the seed text for custom-seeded runs (assumption). FR-8 excludes the seed but FR-3 does not say FR-8 overrides. *Fix:* FR-3 adds "except anything FR-8 lists".
- **[low]** Oracle Run logs are not marked as such (FR-43, FR-23, FR-24) — "nothing else changes" means an Oracle Overlay session writes a normal-looking Run log that Replay would verify as a fair Run. *Fix:* the Run log header records the Oracle flag and Replay refuses to report a verified Run from an Oracle log.

## B. Internal contradictions

- **[high]** The Composite outcome rewards dive-and-die deeper in the pre-win era that SM-C2 says it prevents (§3 Composite outcome, FR-21, SM-C2) — per Run the order is "win, then Score, then depth". SPD's Score rises with depth reached, gold, and exploration (assumption), so between two losing Runs on a paired seed the deeper diver almost always has the higher Score and wins the pair. FR-21's guard only covers "a Brain that dives deeper but wins or scores less". SM-C4 says win rate is near zero for the whole of E4 to E6, which is exactly when this loophole is open. *Fix:* state the loophole and require every Results page to report median death depth against median Score, or define the pre-win Composite as (win, survival-curve rank, Score).
- **[high]** PAUSED and HUMAN cannot both be as described (FR-39, FR-40, UJ-2, §3 Mode) — FR-40: "In PAUSED or HUMAN Mode the human plays with the normal controls." UJ-2: Bash "presses Pause, reads the alternatives, presses Take over, plays two turns". If PAUSED already accepts human play, Take over and HUMAN are redundant; if PAUSED blocks input, FR-40 is wrong. *Fix:* PAUSED = Brain halted, hero input ignored or forwarded (choose one); HUMAN = human input accepted and recorded; write it in the Glossary.
- **[medium]** "One process hosts one Run at a time" versus `--threads T` (FR-2, FR-19, §9 Rig command line, addendum) — the CLI contract exposes threads while every other statement says processes are the default and the isolation spike is not a requirement. *Fix:* rename to `--workers` or define `--threads` as the process count in §9.
- **[medium]** §5 tightens Rule 4 beyond Rule 4 and beyond the PRD's own Search and Evaluation (§5 versus §3 Search, FR-33, FR-34) — "will not reimplement any game rule in any language" versus Rule 4's "abstract tactical model derived from Observations" and the addendum's "One-ply over Codex tables first". *Fix:* mirror Rule 4's sentence in §5.
- **[medium]** UJ-1 omits the Registration that FR-22 makes mandatory (UJ-1 versus FR-22) — the journey runs the Rig then "the Results file is committed"; FR-22: "Every comparison has a Registration committed before its first Run". *Fix:* insert "commits a Registration" before the Rig step in UJ-1.
- **[medium]** The nightly smoke comparison has no Registration (FR-25 versus FR-22) — a daily automated comparison "against the Baseline" cannot be pre-registered by a human each day, and FR-25's "Every registered comparison publishes" implies unregistered comparisons exist. *Fix:* a standing Registration per Baseline version covers the nightly, or the nightly is named a monitor whose output is never cited as a Result.
- **[medium]** The vocabulary diff cannot come from the pinned tag (FR-16 versus §3 Codex) — the Codex is "generated from the pinned upstream code"; vanilla Pixel Dungeon names are not in that code. *Fix:* name a second pinned input (a watabou/pixel-dungeon tag) or move FR-16 to a hand-curated Lore-tier artifact.
- **[medium]** Smoke size versus burn-in versus the UJ-1 climax (FR-20, FR-21, UJ-1, NFR-3) — `smoke` is 25 pairs, FR-21 "does not stop before a burn-in", and UJ-1's climax is "the test accepted". If burn-in is 25 or more pairs, smoke can never accept. *Fix:* state burn-in is smaller than `smoke`, or make UJ-1's climax "undecided with a readable trace" and leave acceptance to `standard`.
- **[medium]** FR-31's Policy list cannot reach FR-31's target (FR-31, SM-3) — "explore, fight in corridors, eat, and descend, sufficient to kill Goo on at least 75%" lists no pick-up, equip, heal, or item-testing behavior; FR-30 exists separately. Either the list is incomplete or the target is the done. *Fix:* "at least these Policies" and the number is the acceptance test.
- **[medium]** SM-3's numbers are only consistent at n=500, which FR-20 calls revisable (FR-31, SM-3, FR-20) — at 500 Runs a 75% observed rate has a lower 95% bound near 71%; "revisable by ADR once throughput is measured" can shrink `standard` and make 70% unreachable at 75% observed. *Fix:* bind the bound to a stated n, or replace it with a maximum interval width.
- **[low]** FR-48 cites the wrong counter-metric — "reported on the upstream page (SM-C4)"; hook count is SM-C5. *Fix:* SM-C5.
- **[low]** Harness versus Rig in UJ-1 — "the Harness runs both Brains headlessly in parallel processes"; FR-19 gives that to the Rig. *Fix:* Rig.
- **[low]** SM-6 requires a verified Replay of an Overlay Run while FR-37 says Replay across a resume is only "verified from E8" — a full sewers Run may span a save. *Fix:* SM-6 says "without a save-and-resume".

## C. Downstream failure

- **[critical]** The Panel has no state machine, no content limits, and no error states (FR-38 to FR-40, NFR-4, UJ-2, §3 Mode) — three Modes are named; the text implies at least these unnamed states: pause-pending during an animation ("shows PAUSED only once the hero is waiting"), Run N in progress, Step in progress, thinking budget exceeded, Oracle, coach (v2), a game modal window open, Run ended, Brain threw, Action rejected (FR-4). No transitions, no owner of each transition, no rule for what "Step" does in HUMAN. No limit for the Goal string, the "one-line" reason, the decision-log retention, or the Belief summary item count. Small windows: "the UX workflow decides" with no minimum size and no collapse rule. *Fix:* add a state and transition table (state, entry condition, allowed controls, what the Panel shows) and a content-limits list, or a "UX must decide" checklist naming each item above.
- **[high]** The Sequential test has no defined per-pair statistic (FR-21, §3 Composite outcome, addendum Rig statistics) — "paired-seed differences of the Composite outcome" and "bounds stated in standardized units": a lexicographic tuple has no difference and no standard unit; the GSPRT needs a scalar with a variance. The addendum defers it to E3 but FR-21 already binds the words. Rank-based, scalarized, and trinomial designs are all admissible and incompatible. *Fix:* FR-21 states "the per-pair statistic is the ordinal comparison (better, equal, worse) of the Composite, and bounds are in that unit as in Fishtest's trinomial model", or explicitly names the E3 ADR as the decision route and removes "standardized units".
- **[high]** FR-26 cannot be done in E3 (FR-26, §6.1, addendum epic map) — "the Runs with the largest Evaluation drop in their final 10 turns" needs the Evaluation, which is FR-33 in E4; E3's Baseline is the random agent. *Fix:* move FR-26 to E4, or keep only "the shallowest deaths" in E3.
- **[high]** FRs whose bullets belong to different epics — FR-9 behavioral form "from E4"; FR-11 (flag in E1, Rig refusal in E3, red border in E5); FR-12 "Brain runs on a worker thread" (an E5 concern in an E1 FR); FR-23 actor "human" (E5); FR-36 "that the Panel shows" (E5); FR-37 resume verification "from E8"; FR-33 SPSA "E6+". The epics workflow cannot size a story with a done in another epic. *Fix:* per FR, tag each consequence with its owning epic, or split the FRs.
- **[high]** Human Actions outside the Action vocabulary break Replay (FR-23, FR-24, FR-40, SM-6) — the human "plays with the normal controls": a shop purchase, a level-up talent choice, a quest reward dialog, an alchemy craft, a quickslot change. None is in the Action list, so the Run log cannot encode them and a fresh Run cannot reproduce them; SM-6 depends on this Replay verifying. *Fix:* state that the Action set is total over hero-affecting UI actions with a completeness test in FR-4, or that a human action outside the set ends Replay-verifiability and the log records it.
- **[medium]** A Seed set does not fix class or challenge flags (FR-20, FR-1, SM-7, Composite) — FR-1 takes class and challenges as inputs; FR-20 lists seeds only. SM-7 "per-class win rate on `standard`" implies several classes times 500 Runs per comparison with no cost stated; comparing Composite outcomes across different challenge flags is invalid (see D). *Fix:* a Seed set entry is (seed, class, challenges), and `standard` is class-stratified with the count per class stated.
- **[medium]** "Every" with no completeness test (FR-14 "every mob, item, ... player-facing text, asset path"; FR-17 "Every mechanics claim the Brain or the docs rely on") — no enumeration exists for what the Brain relies on, so no story can close. *Fix:* the Brain references Rules by ID through an `api` constant set and FR-17's check is "every referenced ID resolves"; FR-14's coverage is checked against the game's own registries.
- **[medium]** Turn granularity versus multi-turn Actions (§3 Action "move to", "rest", "search"; FR-23 "per turn"; FR-27; FR-37) — "move to" a far cell, "rest", and "search" are many hero turns during which the hero is not waiting for input, so "an Observation whenever the hero waits for input", "one record per turn", and "observes every hero turn regardless of who acted" disagree. *Fix:* define "turn" in the Glossary as a Decision point (hero waits for input) and say multi-turn Actions produce one record and are interruptible.
- **[medium]** The embedded observation point implies an unnamed Hook (FR-37, FR-48) — "observes every hero turn regardless of who acted" requires attaching at the hero-ready point in upstream code; no Hook is listed and no decision route is named. *Fix:* name it as an expected Hook in FR-48 or as an E5 ADR row in the addendum.
- **[medium]** "Hero waiting for input" versus modal windows (FR-39, §10 Human control) — level-up talent prompts, option dialogs, and quest windows are input-waits that are not hero-ready; "Mode changes only when the hero is waiting for input" is undefined there. *Fix:* define whether a modal window is an input-wait for Mode purposes and which side (Brain or human) must answer it.
- **[low]** The turn cap is unnamed (§3 Run "or a turn cap") — its value changes Composite outcomes and must be reproducible. *Fix:* the cap is a Registration field.

## D. Game-specific reality checks

- **[high]** Killing Yog-Dzhewa is not a win, and the win has two shapes (SM-1, SM-2, §3 Composite, §3 Action) — (assumption) in SPD the run is won when the hero takes the Amulet and either ends the run there or climbs back to depth 1 and leaves; physical ascension changes enemies and adds a Score bonus. "Kills Yog-Dzhewa and wins a Run" conflates two events; the amulet decision is an input the Action list lacks; SM-2's "highest Score" is dominated by whether the Brain ascends. *Fix:* define win as the game's own Rankings win flag, add "take the Amulet / end the run" to the Action list, and state whether SM-2 requires ascension.
- **[high]** Score depends on challenge flags (SM-2, §3 Composite, FR-20) — (assumption) SPD scales the final score by the number of enabled challenges. Two Runs with different flags are not comparable on Score, so a Composite comparison or a "highest verified Score" without fixed flags is meaningless, and flags can be turned on to inflate SM-2. *Fix:* the Registration and every Seed set fix the challenge flags; SM-2 is reported per flag set, with the no-challenge number as the canonical one.
- **[high]** Cross-Run profile state makes an Overlay Run unreplayable (FR-37, FR-24, SM-6, §3 Observation "journal state") — (assumption) SPD persists per profile the journal Catalog, badges, and a previous hero's remains that appear as a heap in a later run at the depth of death. The Overlay runs in the user's real profile; a fresh headless Replay has none of this, so the journal fields hash differently and a remains heap changes the game. FR-2 isolates the profile for headless Runs only. *Fix:* the launcher gives each Overlay Run an isolated profile as FR-2 does, and the Observation's journal fields are limited to this-Run notes.
- **[medium]** Depth does not identify a floor (FR-19 "depth reached", §3 Composite, Run log "depth") — (assumption) since v2.2 the game has a branch index for the Blacksmith's mining level, so the same depth exists on two branches. *Fix:* Observation and Run log carry (depth, branch); "depth reached" means main-branch depth.
- **[medium]** Meta-Actions a winning Brain needs are missing (§3 Action, FR-4) — subclass choice, armor ability choice, talent point allocation at level-up, quest reward choices (ghost, wandmaker, blacksmith, imp), shop buy and sell, alchemy, pick-up, unequip, talk to an NPC (assumption: all exist at the tag). "talent or ability use" covers use, not choice. FR-4's "Every Action in the Glossary maps to a game input" is satisfied by a list that cannot win. *Fix:* extend the list or state "the Action set is open and FR-4's completeness test enumerates the UI's hero-affecting inputs".
- **[medium]** SM-7 never names the classes (SM-7, FR-5, FR-31) — (assumption) v3.3.8 has six classes; FR-5's benchmark and, by implication, FR-31's Goo target are Warrior-only. *Fix:* SM-7 lists the classes; FR-31 states its class.
- **[medium]** The game's own saves and detached resumes (FR-37) — (assumption) SPD saves on every level change and on close; a user can resume the same save without the launcher, play, and later relaunch with the Overlay. The Run log then has a gap the "boundary recorded" rule does not cover. *Fix:* the launcher refuses to attach to a save whose turn count is ahead of the Run log, or marks the Run unverifiable in the log.
- **[low]** Seed representation (FR-20, FR-2) — (assumption) the game's seed is a number displayed to a human as a letter code, and custom-seeded runs are flagged in the profile. The Seed set files do not say which form they hold or that the Rig starts a custom-seeded run. *Fix:* one sentence in FR-20.
- **[low]** Daily runs (assumption: date-seeded runs with preset flags exist) are neither in nor out of scope. *Fix:* a §5 line: the launcher never starts a daily as a Run.

## E. Measurement honesty

- **[high]** The developer is a leak channel on public seeds (SM-1 "on a public seed", FR-20, Rule 1) — a headline win can be reached by edit-and-rerun cycles on one seed, where each death reveals hidden identities that the next edit encodes in the Action list or a Playbook. The Rig becomes the oracle and the developer the wire; every Rule 1 test passes. *Fix:* SM-1's seed comes from `holdout` or from a fresh set drawn at claim time, and the Results page records how many prior Runs used that seed.
- **[medium]** Pre-registration is bypassable (FR-22) — "refuses a comparison whose Registration commit postdates its first Run": run unregistered, read the outcome, choose bounds, register, rerun; determinism makes the rerun identical. *Fix:* the Rig refuses any two-Brain comparison without a Registration, and the Registration must predate any Run of that Brain-commit pair on that Seed set.
- **[medium]** SM-2 is a maximum and grows with volume (SM-2) — more seeds run means a higher best Score with no change in the Brain. *Fix:* SM-2 is the maximum within one registered pass of a named Seed set version.
- **[medium]** `smoke` at 25 has unknown power (FR-20, open question 2, UJ-1) — the sample-size saving from pairing is unmeasured, yet UJ-1's climax is an acceptance on `smoke`. *Fix:* see B "Smoke size versus burn-in".
- **[medium]** SM-3's 70% lower bound is coupled to a size the PRD calls revisable — see B "SM-3's numbers are only consistent at n=500". *Fix:* as there.
- **[low]** "Fits within a working session" (NFR-3, §10 Cost) and "fast enough" (SM-C1) are undefined while open question 1 says throughput is unmeasured. *Fix:* a number of hours, or "set by the E1 ADR".
- **[low]** "The field is empty: no bot, RL agent, gym, or headless harness exists for SPD" (§12) is an unmeasured claim stated as fact. *Fix:* "the research found none as of its date".
- **[low]** "the research verified the binding Hook is small" (FR-42 provenance) carries no number. *Fix:* the line count, or the research section.
- **[low]** "A deliberately worse Brain is rejected" (FR-21, SM-5) is trivially met against a random agent and says nothing about power. *Fix:* "a Brain worse by a stated effect size".

## Checked and clean

- Rule 2 (license and attribution): §10 keeps upstream's license, names both authors in `NOTICE.md`, requires the unofficial statement in the README, and forbids filing issues upstream; §5 repeats the last point.
- Rule 4 process boundary: §2.1 "in one JVM", §5 "not ... a separate process or over a socket", §10 Runtime "the bot in the same process as the game". Rig parallelism uses whole game-plus-Brain processes, not a bot process. No socket, RPC, or IPC appears anywhere.
- Rule 6 native UI: FR-38's consequence puts the absence of Swing, JavaFX, ImGui, and web views on the classpath under test; §5 restates it. No FR asks for a toolkit the game does not have.
- Rule 7: FR-52 and FR-53 cover ADRs, the ideas ledger, docs-with-code, TODO-with-issue, and issue mirroring.
- Rule 3 `upstream/master`: FR-50, NFR-5, and §5 all forbid it; upgrades are tag-only and the procedure is enumerated.
- Oracle mode: off by default, explicit flag, marked in the Panel, refused by the Rig for ranked comparisons, recorded on every Results page, and not exposable through the Rig command line (FR-11, FR-43, §9, addendum). The only gap found is the unmarked Run log (A, low).
- Module edges: `api` depends on nothing; `brain` on `api` only; ArchUnit and a resolution-time check both enforce (FR-7, §10). The `overlay` module depending on `core` is consistent with Rule 6 and does not touch the Brain's edges.
- Thread confinement: FR-12 and NFR-4 agree (Brain on a worker thread over an immutable Observation, Panel writes on the render thread).
- Network and telemetry: NFR-8 forbids both; no FR needs a network call.
- Determinism test and fairness suite in CI on every pull request: FR-2, FR-8, NFR-1, SM-8 agree.
- Searched for and did not find: any FR that reads a save file into the Brain; any raw-model-field access in the Observer's description; any rollout on the raw saved game (forbidden in §3 Search, FR-6, FR-34); any turns-per-second promise (NFR-3 refuses one); any mobile target; any claim that the Rig or Overlay can enable Oracle without the launch flag.
