## Intent

**Problem:** Every number the rig will publish is measured on a set of Runs, and a skeptic who
cannot obtain the exact set cannot check the number. Nothing in the repository names a seed set
yet, so there is nothing for a Results page to cite and nothing for a Registration to version.

**Approach:** Five committed, versioned files of (seed, hero class, challenge flags) triples —
`smoke` 25, `standard` 500, `holdout` 500, `bosses` 100, `goo` 400 — generated by one task from a
stated derivation, so a stranger can both read the set and reproduce it, and CI fails if a
committed file no longer matches. `holdout` is refused to a development read at the door, because
a set that leaks into development stops being a holdout.

## Boundaries & Constraints

**Always:** A seed set is an `api` value with a schema version, written by the canonical writer, so
what a Results page and a Registration name is a type and not a filename. Every triple is in the
game's own domains, read from the pinned code: a seed is at least 0 and under `26^9`
(`DungeonSeed.TOTAL_SEEDS`), a hero class is one of the game's six, challenge flags are 0 through
`Challenges.MAX_VALUE`. Each file carries its set's name and version, and each triple carries the
seed's `@@@-@@@-@@@` code as the game writes it, since that is what a human types into the game to
run one. One task writes every set; regenerating and committing is the only way a set changes.

**Ask First:** Nothing here. The sizes are the PRD's, the derivation is this story's, and both are
revisable by ADR once E3 has measured throughput — which this story records rather than resolves.

**Never:** Do not draw a seed at generation time from an unseeded source: a set nobody can
reproduce is a set a skeptic has to take on trust. Do not run any Run in this story — no harness,
no game boot; these are files and their guards. Do not let a development path read `holdout`.
Do not choose set sizes by argument here; the PRD fixed them and the ADR will revise them.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| The five sets | the committed files | each holds its stated size, every triple in the game's domains | N/A |
| Regeneration | the task run twice | byte-identical, and identical to what is committed | drift fails naming the file and the command |
| A hand-edited set | one seed changed | the drift check fails | names the file and the command |
| A seed out of range | a triple at `26^9` | refused when the value is built | names the seed and the bound |
| An unknown hero class | a name the game does not have | refused when the value is built | names the class and the six |
| Challenge flags past the mask | 512 | refused | names the value and `MAX_VALUE` |
| A development read of `holdout` | `load("holdout")` | refused | names the set and what it is for |
| A published read of `holdout` | the read that states its reason | allowed, and the reason is carried | N/A |
| The `goo` set's size | 400 triples, all Warrior, no flags | an observed 75% gives a lower bound above 70% | the bound is computed, not asserted by hand |

## Spec Change Log

## Design Notes

**Why derived rather than drawn.** A set drawn from an unseeded source and committed is a set a
skeptic must take on trust: the file is the only evidence, and nothing says the draw was not
repeated until it flattered someone. A set derived from a named constant and an index is
reproducible by anyone, and the committed file is then a convenience that CI proves — the same
argument the Codex makes about its tables, and the same drift check.

**Why the seed code is carried beside the number.** `5429503678975` is what the engine takes and
`ZZZ-ZZZ-ZZZ` is what a human types into the game's own seed box. A stranger checking a published
number will do the second, so the file carries both.

**Why `holdout` is guarded at the door.** FR-20 makes it testable: the rig refuses a development
comparison on `holdout`. A guard anywhere later is a guard someone routes around; a `load` that
refuses unless the caller states why it is publishing is the narrowest place to put it.
